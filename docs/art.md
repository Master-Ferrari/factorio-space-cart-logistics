# Рисование рельса
> Часть ТЗ Space Cart Logistics — индекс в [../readme.md](../readme.md). Смежное: как маска ↔ (прототип, direction) и морф — [hard-decisions.md](hard-decisions.md); вьюпорт GUI — [signals-and-gui.md](signals-and-gui.md).

**В игре сейчас (атласы из 3D):** пути — `graphics/atlas_rails_layer2.png` (8×8 ячеек по **80 px**, 640×640), подложка — `graphics/atlas_base_layer1.png` (16×16 по 80 px, 1280×1280); `scale = 0.5`, ячейка = 1.25 тайла, центр ячейки = центр сущности. Собирает `3d/tiling/compose_atlas.py base|rails` (PNG сразу в `graphics/`), PSD для ручной правки — `3d/tiling/render/atlas_base.psd`, `atlas_rails.psd`: правишь PSD → сохраняешь игровой слой PNG поверх файла в `graphics/` (размер листа и раскладку не менять). Повторный прогон `compose_atlas.py` перезапишет и PSD, и PNG. Ниже — исходный контракт мок-листа `rail.png` (64 px), раскладка та же.

Финальный арт — **один лист 64 ячейки** (8×8, 64×64 px/ячейка, 512×512; `scale = 0.5` → 1 тайл). Рисуется вручную, чтобы корректно сводить стыки/кресты (over/under, единые узлы — не простым наложением). Мод-сторона (v2.5): каждый из 22 прототипов берёт 4 ячейки листа в `integration_patch` (Sprite4Way, `x`/`y`-офсеты в лист: north = ячейка rep-маски, east/south/west = rep, повёрнутый CW ×1/2/3); в runtime маска = (прототип, direction), морф — rails.lua. Арт доходит до краёв ячейки (стыковка соседей). Движок ячейки **не вертит** — каждое направление Sprite4Way ссылается на ячейку своей маски в листе, так что контракт для художника не меняется: 64 независимые ячейки. «Настоящие» тени — отдельным таким же 64-листом на shadow-слое. Всё — часть entity, без LuaRendering. Для хруста на близком зуме можно 128 px/ячейку → лист 1024×1024, `scale = 0.25`.

**Контракт «бит → ячейка»** (раз и навсегда, общий для арта и кода):
- Биты: `0=N–S, 1=E–W, 2=N–E, 3=N–W, 4=S–E, 5=S–W`. `mask` = OR активных (0..63).
- Ячейка = `mask` row-major, 8 в ряд: `col = mask & 7`, `row = mask >> 3`. mask 0 — верх-лево, 63 — низ-право.
- **Ячейка 0 (mask 0)** = все пути выключены: все 6 путей нарисованы убранными в корпус (не прозрачная).

**3D-арт тайла (сборка — [3d/tiling/tiling.py](../3d/tiling/tiling.py), меши автора `3d/to_claude.fbx`)** — два независимых слоя:
- **Слой 1 — подложка + весь декор**, 2^8 вариаций по 8 соседям-тайлам. Рукав креста: сосед есть — срез по краю, нет — торец. Угловая рамка дырки — по тройке (орто, диагональ, орто): 000 крючок, 100/001 стенка к соседу, 010 диагональный канал, 110 фаска внутреннего угла, 101/011/111 — ничего.
- **Слой 2 — пути**, 2^6 вариаций по маске выше. Каждый путь есть всегда: включён — `ON`, выключен — `OFF` (ушёл в корпус, неактивен). Общие куски (центр, наконечник у края) — `ON`, если включён хоть один путь через них.
- **GUI-вьюпорт (отдельная графика, НЕ этот лист):** окно собирает тайл стопкой из 7 текстур с альфой 256×256 — `gofarovich-scl-vp-base` + `gofarovich-scl-vp-<conn>` (6 цветных путей), `graphics/viewport/`, рисует `tools/gen_viewport.ps1`. Слои кладутся друг на друга negative-margin'ом и растягиваются на вьюпорт (`stretch_image_to_widget_size`); порядок наложения = порядок битов. Лист `rail.png` остаётся только для арт-сущности в мире.

**Моки (сейчас):** арт делает сам агент программно. Для каждой `mask` рисует активные сегменты (прямые — линиями, повороты — дугами r=0.5) в 64×64 и складывает в 8×8 по тому же контракту; наложением — для моков сойдёт. Аналогично мок каретки: 16 кадров-стрелок. Реальный арт автор подставит позже, контракт не меняется. **На первых порах сидим на моках.**
